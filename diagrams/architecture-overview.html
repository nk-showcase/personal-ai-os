1

What it does

  • Agentic coding from a phone: send a task in chat — a coding agent on the server edits code, commits, and pushes to a working branch, even when the personal computer is off.
  • Personal domains driven by chat: each feature (the published demo is a notes domain) reuses the same machinery — queue, worker, encrypted store, replies.
  • Self-updating: services restart on new code only if it compiles, so a bad edit cannot wedge the system.
  • Always on: runs 24/7 as three system services on a dedicated server.

Coding worker

OS user: ai-os

Runs the coding agent: edits, commits, pushes to a working branch.

agent session, local to server disk

integration keys, chat token

Hard boundary, not a convention: three separate OS user accounts connected only through a durable task queue — each service holds only its own credentials, and units refuse to start if the account split is missing.
3

Security controls

Allow / Deny gate on the phone

Irreversible actions (push to main, deletes, downloads, outbound sends) wait for explicit approval. On by default, fail-closed: no answer in 5 min = deny.

Encryption at rest

Personal free text in SQLite is envelope-encrypted: per-row data key wrapped by a master key held only by the keyed worker.

Secret manager, per-service scope

Secrets live in a machine-account secret manager; each service gets a read-only token for exactly its own folder. Code uses secret names, never values.

Log redaction

A filter scrubs secret-shaped values before anything reaches logs; a value-free scanner ships for auditing them.

Durable queues

Tasks and pending approvals survive restarts — a crash does not silently drop work or approvals.

Compile-gated auto-restart

A restart takes new code only if it byte-compiles — no crash loops on a broken edit.
